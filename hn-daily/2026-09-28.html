Daily Hacker News for 2026-09-28

The 10 highest-rated articles on Hacker News on September 28, 2026 which have not appeared on any previous Hacker News Daily are listed below, with Chinese summaries for quick reading.

  1. Ember-1
    comments

    Fireworks Research 推出基于 Kimi K3 的专用模型 Ember-1，旨在保留 K3 高质量推理与编程能力的同时降低使用成本。该模型通过新型训练算法精简冗余推理过程，可在 Agent 及多轮对话等复杂工作负载中减少 35%–50% 的推理 Token 消耗。在 Bedside Bench 等公共基准测试、Fireworks 内部部署以及客户生产环境 Live A/B 测试中，Ember-1 均在保持同等回答质量的前提下显著提升了成本效益。

  2. Self-Hosting on the Dark Web
    comments

    作者 David Álvarez Rosa 分享了将其个人静态博客作为 Tor 隐藏服务（.onion 地址）部署在暗网上的具体实践。配置过程包括修改 Tor 配置文件指定专用目录与端口映射，并设置 Nginx 服务器块监听本地 8080 端口以提供服务。为防止静态站点链接指向明网域名，作者使用 Hugo 为 .onion 域名单独构建副本，并通过 GitHub Actions 和 rsync 实现了双网版本的自动打包与同步部署。

  3. Owed a billion dollars in Nvidia stock
    comments

    1993年担任英伟达（NVIDIA）早期技术顾问的 Eric Gullichsen，于2024年查阅旧文件时发现其期权合同原本规定为一年内完全归属，而非公司在1996年执行的四年归属。若按原合同计算，历经多次拆股后他少获得的期权现相当于450万股股票，价值约10亿美元。虽然英伟达未否认合同真实性，但由于时隔30年已远超诉讼时效，作者与律师评估后最终放弃诉讼维权。

  4. AI companies in race to demonstrate their model most threatening to humanity
    comments

    随着对人工智能毁灭人类风险的担忧日益增加，OpenAI 和 Anthropic 等 AI 巨头正掀起一场新的营销竞赛，竞相向客户证明自家模型最具毁灭人类的能力。这些公司通过吹嘘 AI 智能体自主入侵 Hugging Face 及澳大利亚医保数据库、甚至散布极端危险警告等“威胁演示”来吸引消费者。不过专家表示，这类末日场景距离现实依然遥远，在很长一段时间内，人类自身仍是毁灭自己的最大可能性。

  5. Coding Is Not Solved
    comments

    本文反驳了“AI已彻底解决编程”的流行观点，指出代码编写只是达成理解的副产品，软件的主要成本在于维护、安全性与可靠性等非功能需求。作者强调在医疗、金融等低风险容忍度领域必须具备责任制，而AI无法被问责且存在逻辑局限，因此开发者不能放弃对代码的理解与掌控。盲目推崇AI生成代码会导致服务质量下降，开发者应警惕过度依赖AI带来的技能退化，注重建立深层知识体系以维持长期竞争力。

  6. MongoDB CEO resigns to join Meta
    comments

    MongoDB 总裁兼 CEO Chirantan "CJ" Desai 离职并加盟 Meta，出任新设立的首席企业平台官（Chief Enterprise Platform Officer），直接向扎克伯格汇报以拓展企业级 AI 业务。MongoDB 董事会已指定前 CEO Dev Ittycheria 重新担任临时 CEO，并启动新任 CEO 的遴选工作。尽管高层人事变动引发市场波动，MongoDB 官方仍重申了第三季度及全年的财务预期。

  7. Pirating the Pirates
    comments

    文章探讨了电影官方“修复”与导演修订（如《黄金三镖客》《星球大战》）往往导致原始影院剪辑和音轨失真的问题。面对商业厂牌受制于版权、预算及导演个人意愿的困境，民间影迷与非官方团队通过胶片扫描、音轨缝合（Remux）及民间重建项目（如 Project 4K77）自发开展电影保存。这种不受商业与法律约束的影迷网络填补了官方发行的缺陷，为影史保留了忠于历史原貌的经典电影遗产。

  8. The problem is not AI code, but not knowing about system architecture or intent
    comments

    本文探讨了AI生成代码时代面临的核心挑战，指出真正的危机不在于AI代码质量本身，而在于开发团队过度依赖AI工具，导致无人再关注系统架构与设计意图。在管理层盲目追求交付速度的压力下，工程师往往未经审查便直接发布AI生成的代码，削弱了团队的思考与解决问题能力。作者强调软件可维护性依然是最终考验，虽然AI极大地降低了生成代码的门槛，但架构思维、产品品味与人类的主导编排作用依然不可替代。

  9. Windows 11½
    comments

    Windows 11½（Definitely Not Windows）是一个独立非官方的交互式恶搞项目，旨在幽默讽刺现代软件中的订阅模式、广告嵌入、AI功能、强制更新以及存储空间提示等现象。该网站并非微软官方产品，不会索取或收集用户的密码、信用卡等个人凭据，页面中安装应用、购买订阅和触发更新等按钮操作均为虚构的娱乐效果。此外，网站还包含了由 Clippy 管理的匿名访客计数器，仅通过浏览器存储的随机 ID 记录访问序号，无需收集任何个人身份或指纹信息。

  10. Sonnet 5.5
    comments

    Anthropic 推出 Claude Sonnet 5.5 模型，相比 Sonnet 5 生成速度提升 30% 以上，单任务成本最高可降低 30%。该模型作为 Opus 5.5 的高效低成本补充，擅长明确的日常任务、代码修复及设计文档制作，在 Terminal-Bench 4.0 等 Agentic Coding 及知识工作评估中取得显著性能跃升。此外，它是首个配备网络安全防护与反蒸馏机制的 Sonnet 模型，目前已在 Claude 平台及各大主流云服务平台全面上线。
