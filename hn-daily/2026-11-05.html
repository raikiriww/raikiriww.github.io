  6. sshole
    comments

    该漏洞（称为 sshole）影响在基于 musl libc（如 Alpine Linux、OpenWrt 等）且未启用 PAM 的系统上运行的 OpenSSH 服务。由于 musl 的 sha512 crypt 实现对超过 256 字节的密码直接返回代表失败的单字符“*”，而 OpenSSH 为防范计时攻击会借用其他有效账户的 salt 对无密码账户进行哈希验证，导致影子文件中以“*”锁定的账户与 musl 失败时返回的“*”产生意外匹配。攻击者向此类无密码账户输入 257 至 1024 字符的任意密码即可成功登录，受影响环境需升级至 OpenSSH 10.6p2 或通过禁用密码认证进行防护。

  7. Discord is ditching Electron and its new app uses less RAM
    comments

    据 The Verge 报道，Discord 宣布将彻底放弃高内存占用的 Electron 跨平台框架，把桌面客户端完全迁移至 Rust 语言以提升性能。首席技术官 Stanislav Vishnevskiy 表示，重构将一并取代 React Native，移动端在保持原生界面的同时将通过 Rust 与桌面端共享应用逻辑代码。测试截图显示新版 Windows 客户端内存占用已骤降至约 290MB，相较现有版本动辄突破 1GB 有显著改善，官方预计很快面向用户开展测试。

  8. Alpine Linux Security Advisory: OpenSSH-server password authentication bypass
    comments

    Alpine Linux 发布安全通告指出，未启用 PAM 构建的 openssh-server 存在密码认证绕过漏洞，攻击者无需密码即可登录密码字段为星号（*）的无密码或纯公钥账户。该漏洞源于系统存在其他含密码散列的用户时，攻击者若输入超过 256 字节的超长密码，musl libc 的 crypt() 函数会返回星号错误标识，导致与借用盐值的目标账户字段错误匹配而放行登录。该问题影响 Alpine 3.16 至 3.24 及 edge 版本，官方建议立即更新 openssh 软件包并手动重启 sshd，或将配置中的 PasswordAuthentication 设置为 no 以阻断攻击。
